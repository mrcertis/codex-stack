# Установка: инструкция для агента

Выполняй только по запросу владельца. Цель — рабочий Codex Stack с проверками,
сохранёнными прежними настройками и понятным отчётом.

## 1. Определи окружение и хост

Определи, для какого хоста ставится стек: **Claude Code** (по умолчанию, если ты
работаешь в нём) или **Codex**; для обоих — только по явной просьбе. Дальше
выполняй команды выбранного хоста из [INSTALL.md](INSTALL.md).

Проверь ОС, хост и его версию, Git, Node/npm, Python, uv, Bun и доступ к сети.
Прочитай применимые CLAUDE.md или AGENTS.md. Уточни нестандартный
CLAUDE_CONFIG_DIR или CODEX_HOME, если он используется.
Для macOS/Linux дефолты: Tools в ~/Documents/Codex/Tools, общий vault в
~/Documents/Codex/Knowledge, WIKI_ROOT — подкаталог LLM Wiki внутри него.
Если пользователь уже ведёт Wiki, выясни её область; проектный vault не превращай
в глобальный автоматически.

Прочитай только относящиеся к установке настройки. Не печатай ключи, заголовки
авторизации, полный settings.json, `~/.claude.json` или config.toml.
Инвентаризируй имена MCP (`claude mcp list` или `codex mcp list`), пути skills
и версии CLI. Не обходи реестр проектов без запроса на такой обзор.

## 2. Сохрани существующее

Создай приватную резервную копию изменяемых файлов, если они есть:
для Claude Code — CLAUDE.md, settings.json и PROJECTS.md в `~/.claude`;
для Codex — AGENTS.md, config.toml, hooks.json, RTK.md и PROJECTS.md.
Папка backup должна быть вне публичного репозитория.
Сохрани контрольную сумму PROJECTS.md, чтобы проверить неизменность в конце.
Не заменяй модель, режим разрешений, permissions, sandbox, approval policy,
trust и чужие MCP/hooks.

## 3. Установи основной набор

Следуй [INSTALL.md](INSTALL.md) по порядку. Повторная установка начинается с
проверки, не с удаления. Установленное и рабочее пропускай; обновление версии —
отдельное решение. Перед запуском upstream-скрипта прочитай его и закрепи в отчёте
commit или версию. При изменении синтаксиса используй README и --help этой версии.

Используй Context7 и официальную документацию хоста для проверки конфигурации.
Установи grill-with-docs вместе с grilling и domain-modeling и обязательный Z.A.E.B.A.L.
Установи Ponytail как плагин выбранного хоста по INSTALL.md; перед выполнением
его hooks проверь команды и отметь их состояние отдельно от наличия плагина.
Emil можно установить глобально. Глобально установи stack-start и хуки стека:
они направляют агента к подготовке нового проекта по обычному запросу пользователя.
Локальный набор, включая Impeccable, подготавливается сразу до интервью; не жди
решения о наличии или виде UI. Дизайн запускается после интервью по необходимости.
Не устанавливай все плагины Claude из исходного KISA: ставь только перечисленное
в [каталоге](../plugins.md).

## 4. Установи глобальные инструкции

Шаблон закрепляет обязательное уточнение и подтверждение требований для новых
продуктов и изменений существующих проектов. Исключение — однозначные мелкие
правки без выбора поведения. Интервалы, пороги и поведение при сбоях агент
не назначает самостоятельно; новые продуктовые вопросы уточняет и во время работы.

Выполни из checkout `python3 scripts/install_config.py --host claude` (или
`--host codex`) с нужными путями, проверь dry run и повтори с `--apply`.
Он подставит абсолютные TOOLS_ROOT и WIKI_ROOT и добавит поставляемые хуки;
подробности в [HOOKS.md](HOOKS.md).

- **Claude Code:** [шаблон](../global-config/CLAUDE.md) ставится блоком между
  маркерами Codex Stack в `~/.claude/CLAUDE.md`. Остальное содержимое файла,
  включая блоки gstack, RTK или ObsidianDataWeave, сохраняется. Не дублируй
  правила стека вне блока.
- **Codex:** старый глобальный AGENTS.md полностью заменяется
  [шаблоном](../global-config/AGENTS.md); не объединяй старые разделы с новыми.
  Если AGENTS.override.md затеняет шаблон, сначала согласуй архивирование этого
  отдельного файла. Не удаляй его автоматически.

Context7, Impeccable и emil-design-eng уже есть в маршрутизации шаблона.
Не включай MTGA без желания владельца. Его повторное включение выполняется отдельно.
Не копируй весь каталог skills в правила — достаточно назначения и точек входа.

## 5. Подключи MCP и hooks

Для Claude Code добавь серверы командами `claude mcp add --scope user` из INSTALL.md
или по [mcp.claude.example.json](../global-config/mcp.claude.example.json); для Codex
слей выбранные записи [mcp.example.toml](../global-config/mcp.example.toml)
с существующей конфигурацией. Не дублируй сервер под новым именем.
Для Context7 используй OAuth либо ключ из окружения. Вход выполняет владелец.
Не переносить секреты в репозиторий. Desktop должен получать переменную в своём
окружении, а не только в случайном терминале.

Подключи [хуки стека](HOOKS.md), обязательный [Z.A.E.B.A.L.](ZAEBAL.md) и
Ponytail по [инструкции](INSTALL.md#ponytail).
Проверка hooks — часть подключения: в Claude Code через `/hooks`, в Codex — trust
в интерфейсе; не меняй trust за пользователя.
Wiki доступна через глобальные правила и без hooks, но неподдерживаемые или
несработавшие hooks отмечай как незавершённую часть установки. Не копируй личные
плагины автора.

## 6. Проверь результат

Открой новый сеанс для проверки MCP/skills. Пройди [VERIFY.md](VERIFY.md).
Context7 должен вернуть документацию, а не только числиться в конфиге.
Agentation должен ответить через MCP; браузерный тест требует выбранного проекта
или согласованной временной demo-страницы. Не добавляй компонент во все приложения.
Временные тестовые изменения держи отдельно от пользовательских проектов.

## 7. Отчитайся

Перед завершением пройди с владельцем [AFTER-INSTALL.md](AFTER-INSTALL.md).
Доведи доступную настройку до результата, покажи шаг входа в Context7 и проверки
hooks, если они ещё нужны. Объясни, что панель Agentation подключается к каждому
нужному приложению; при отсутствии проекта оставь это конкретным следующим шагом.
Не заканчивай отчётом «установлено», скрывающим незавершённые входы и подключения.

По компонентам: версия/commit, место установки, конкретная проверка и её результат,
остаточные действия. Отдельно перечисли входы, состояние hooks и непроверенные сценарии.
Сверь checksum реестра и сохранность чужих настроек. Не говори «всё работает», если
проверено только наличие файлов. Не публикуй локальный отчёт с путями и секретами.

При обновлении: повтори backup → change → focused verification. Для отката
восстанови только свои изменения из backup, не затирая более поздние правки.
