# Обновление со старой версии стека

Для тех, у кого стек уже стоит: с gstack, старым AGENTS.md, Tools и Wiki в
`~/Documents`. Что изменилось и почему — в [CHANGELOG](../CHANGELOG.md).

Напишите агенту в Codex (или Claude Code):

> Обнови мой стек по https://github.com/mrcertis/codex-stack/blob/main/docs/UPGRADE.md. Перед каждым удалением покажи список и спроси меня.

## Правила для агента

- Выполняй шаги по порядку; каждый шаг — резервная копия → изменение → проверка.
- Ничего не удаляй без явного «да» владельца. Перед вопросом покажи список путей
  и их размер (`du -sh`). Удаление — перенос в Корзину, а не `rm`, если upstream-
  скрипт удаления не выбран владельцем явно.
- Не печатай ключи и полные конфиги; показывай только найденные имена и пути.
- Не трогай PROJECTS.md и проекты пользователя без отдельного разрешения.
- Шаг не получился — остановись, опиши причину и спроси, как быть.

## 1. Инвентаризация и резервная копия

Найди и покажи владельцу:

- `~/.codex/AGENTS.md`, `config.toml`, `hooks.json`, `PROJECTS.md`;
- `~/.claude/CLAUDE.md`, `~/.claude/settings.json`, если есть Claude Code;
- установки gstack: `~/.claude/skills/gstack`, `~/.codex/skills/gstack*`,
  `~/.agents/skills/gstack*`, клон в каталоге Tools, `~/.gstack`;
- где лежат Tools и Wiki и находятся ли они в iCloud (`~/Documents`, `~/Desktop`
  при включённой синхронизации «Рабочий стол и Документы»).

Скопируй найденные конфиги в приватную папку резервных копий вне iCloud и назови её.

## 2. Удаление gstack

gstack больше не используется: его место занял GSD. gstack занимал много места
на диске (клон, браузер, состояние в `~/.gstack`) и добавлял в AGENTS.md и
CLAUDE.md объёмные разделы, которые раздували контекст каждой сессии.

1. Покажи владельцу найденные каталоги gstack с размерами и спроси, удалять ли.
2. После «да» используй официальный способ из раздела
   [Uninstall](https://github.com/garrytan/gstack#uninstall) README gstack:
   скрипт `bin/gstack-uninstall` из установленной копии убирает skills, ссылки,
   `~/.gstack`, браузерные процессы и хуки Claude Code. Скрипт удаляет файлы сам:
   владелец должен согласиться именно на него. Если владелец хочет Корзину —
   перенеси туда каталоги из списка по шагам ручного удаления того же раздела.
3. Убери оставшиеся хуки gstack: записи в `~/.claude/settings.json` и
   `~/.codex/hooks.json`, команды которых указывают в каталог gstack (SessionStart,
   PreToolUse/PostToolUse для AskUserQuestion, Stop). Без установки они падают
   на каждом событии.
4. В глобальных и проектных AGENTS.md / CLAUDE.md найди разделы `## gstack`
   и `## Skill routing`. Глобальный AGENTS.md заменит шаг 4; в проектных файлах
   удаляй разделы только с согласия владельца по каждому проекту.
5. Кэш Playwright (`~/Library/Caches/ms-playwright/` на macOS) общий с другими
   инструментами — не трогай без отдельной просьбы.

## 3. Tools и Wiki — из iCloud

Нужно, только если они лежат в папке, которую синхронизирует iCloud. Новые пути
по умолчанию: `~/tools` и `~/Knowledge` (корень Wiki — `~/Knowledge/LLM Wiki`).
Согласуй пути с владельцем.

1. Найди конфликтные копии iCloud (`* 2.md`, `* 2.db` и т.п.), сравни с оригиналами
   и покажи владельцу; лишние — в Корзину после «да».
2. Скачай файлы, выгруженные в облако: на macOS их видно через
   `find <папка> -flags +dataless`; прочитай каждый такой файл, чтобы он скачался.
3. Скопируй каталоги на новое место с сохранением атрибутов и сверь `diff -r`.
4. Замени старый путь во всех местах, где он записан: AGENTS.md (шаг 4 сделает это
   установщиком), `config.toml` и MCP-записи, хуки, `config.toml` ObsidianDataWeave
   (`vault_path` и `[memory] db_dir`), регистрация vault в приложении Obsidian.
   Виртуальное окружение `.venv` после переноса пересоздай или исправь в нём пути.
   Найди остатки поиском старого пути по `~/.codex`, `~/.claude` и новому `~/tools`.
5. Проверь: `wiki_lint.py <space> --strict` по каждому space, поиск по Wiki,
   MCP из перенесённых каталогов отвечают. Старую папку — в Корзину после «да».
6. Предложи локальный git в vault (`git init`), если Wiki нужна только на этом Mac.

## 4. Новые глобальные правила

Из свежего checkout этого репозитория выполни dry run и применение
[установщика](INSTALL.md#глобальные-правила) с новыми путями; для Claude Code
добавь `--claude-home "$HOME/.claude"`. Старый AGENTS.md уходит в резервную копию,
блок MTGA переносится. Если в старом файле были личные правила владельца,
покажи их и спроси, нужно ли перенести их в проектные AGENTS.md.

## 5. GSD, Ponytail, MTGA, Refero

- GSD: установи или обнови по [INSTALL](INSTALL.md#gsd-core) в Codex и, если
  используется, в Claude Code; добавь `~/.gsd/defaults.json`. В существующих
  проектах GSD предложи `config-set workflow.inline_plan_threshold 5`.
- Ponytail: обнови до 5.2.0 в обеих средах по [INSTALL](INSTALL.md#ponytail),
  подтверди доверие хукам в `/hooks`.
- MTGA: если не стоит — поставь и включи по [INSTALL](INSTALL.md#mtga).
- Refero: предложи владельцу, объяснив, что живой поиск требует платного тарифа;
  ставь только после согласия. [Как подключить](INSTALL.md#refero--по-желанию).
- Локально установленные в проектах grill-with-docs, grilling и domain-modeling
  можно оставить: они не мешают GSD. Удаляй только по просьбе.

## 6. Проверка и отчёт

Открой новую задачу и пройди [VERIFY.md](VERIFY.md). В отчёте раздели: что удалено
(с путями и освобождённым местом), что перенесено, что установлено и проверено
реальным действием, что требует входа или доверия к хукам, где лежат резервные копии.
