# Codex Stack — mrcertis

Мой набор инструментов для работы с AI-агентами: от постановки задачи до кода, дизайна, проверки и проектной Wiki. Основа — [KISA Stack](https://github.com/howdeploy/kisa-stack), адаптированная под **Claude Code** и **Codex** и дополненная **Impeccable, Emil Design Engineering и Context7**.

Это открытая сборка инструкций и шаблонов. Она помогает воспроизвести подход, не копируя чужие ключи, личные проекты и настройки компьютера. В Claude Code правила стека добавляются отдельным блоком в `~/.claude/CLAUDE.md`, остальное содержимое файла сохраняется. В Codex старый глобальный AGENTS.md сохраняется в приватной резервной копии и полностью заменяется шаблоном стека. Остальная конфигурация сохраняется.

## Быстрый старт

1. Установите и авторизуйте Claude Code (основной сценарий) или Codex. Нужны Git, Node.js LTS; для полного набора также Python 3.11+, uv и Bun.
2. Напишите агенту:

   > Установи и настрой мне этот стек: https://github.com/mrcertis/codex-stack. Следуй инструкции docs/AGENT-SETUP.md из репозитория и проверь результат.

   Агент сам получает репозиторий, читает инструкцию и выполняет настройку.
3. Пройдите [«Что делать после установки»](docs/AFTER-INSTALL.md): вход в Context7, проверка хуков и подключений. Agentation подключается также к каждому нужному приложению.
4. Откройте проект и пишите как обычно: «Давай сделаем сайт для [название проекта]». Названия skills и команды знать не нужно.

**Вручную:** [полная установка](docs/INSTALL.md). **Для агента:** [порядок настройки](docs/AGENT-SETUP.md). **На каждый день:** [короткая шпаргалка](docs/USAGE.md).

## Как это работает

Вы пишете идею обычными словами. Хук направляет агента к стартовому skill, агент сразу подготавливает локальный набор нового проекта, включая Impeccable. Затем проводит интервью по процессу grill-with-docs, фиксирует требования и, если нужен интерфейс, переходит к Impeccable для выбора дизайна. После этого — документы, код и проверка. [Как устроен старт](docs/NEW-PROJECT.md).

Установка Impeccable не зависит от заранее выбранного UI: визуальное решение выбирается уже с его помощью. Для проекта без интерфейса skill остаётся доступным, но дизайн-процесс не запускается.

Уточнение требований обязательно и для новых функций в существующих проектах: вопросы → подтверждение требований → реализация. Однозначные мелкие правки выполняются сразу. Агент не придумывает интервалы обновления, сроки устаревания данных и поведение при сбоях; новые продуктовые вопросы во время работы согласуются до реализации зависимой части. [Глобальное правило](global-config/AGENTS.md#обязательное-уточнение-требований-перед-реализацией).

Wiki одна для общего знания, внутри отдельные spaces. Реестр проектов приватный. Просьба «проверь проект» разрешает чтение, но не изменения. Запись в Wiki — по явному запросу.

## Совместимость и ограничения

- Основной сценарий: локальный Claude Code на macOS/Linux; Codex поддерживается тем же установщиком с `--host codex`. На Windows команды shell выполняются в WSL; нативные пути и менеджеры пакетов требуют адаптации.
- Конфигурации Claude Code и Codex не взаимозаменяемы: в каждом шаге инструкции свои команды для каждого хоста. Ставьте стек только для того хоста, которым пользуетесь.
- MCP, skill, CLI и плагин — разные сущности. Наличие skill не означает, что MCP подключён.
- Это не обещание установки всего стека за пять минут. Авторизация, браузеры, hooks trust и проектные интеграции проверяются отдельно.
- Основные инструкции сверены 10 сентября 2026, Ponytail — 24 сентября 2026, команды Claude Code — 10 октября 2026. Upstream меняется; после обновления повторяйте проверки. См. [статус проверки](docs/VERIFY.md).
