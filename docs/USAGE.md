# Коротко: как работать

Опишите результат обычным языком. Перечислять все skills в каждом запросе не нужно.

| Задача | Пример запроса |
|---|---|
| Начать проект | «Давай сделаем сайт для [название проекта]» |
| Продолжить работу | «Давай теперь сделаем личный кабинет» |
| Исправить ошибку | «Кнопка отправки не работает, почини» |
| Подключить сервис | «Добавь вход через Google» |
| Дизайн | «Страница выглядит скучно, давай переделаем» |
| Взаимодействие | «Это окно открывается слишком резко» |
| Проверить изменения | «Посмотри, всё ли нормально сделали» |
| Проверить сайт | «Проверь, нормально ли всё работает» |
| Замечания на странице | «Я оставил замечания, поправь» |
| Разобраться в коде | «Как здесь устроена авторизация?» |
| Исследование | «Посмотри, как это делают конкуренты» |
| Проекты | «Что сейчас с этим проектом?» |
| Wiki | «Сохрани это решение в нашей Wiki» |

Это примеры обычной речи, не обязательные формулировки. Агент сам выбирает skills
по задаче и их описаниям. Если не хватает контекста, спрашивает о результате,
который вам нужен. Выбирать инструмент за него не требуется.

Для нового проекта агент сначала подготавливает локальные skills, включая
Impeccable. Затем интервью → требования → дизайн, если нужен → реализация → проверка.
Это маршрут выбора, а не обязательный запуск всех инструментов при каждом изменении.

[Полный процесс старта](NEW-PROJECT.md). [Z.A.E.B.A.L.](ZAEBAL.md) — обязательная
часть стека; при срабатывании агент следует уровню протокола и проверяет ложный сигнал.

Если инструмент не появился, начните новую задачу, проверьте путь установки и
его ошибки. Не повторяйте установку вслепую. Проверки — в [VERIFY.md](VERIFY.md).
