# Начало нового проекта

Напишите: «Давай сделаем сайт для [название проекта]» или «Хочу бота для записи
клиентов». Агент сам выбирает инструменты и задаёт вопросы о продукте.

Порядок: идея → Impeccable в проект → `gsd-new-project` (интервью, требования,
дорожная карта) → фазы GSD: обсуждение → план → выполнение → проверка.
В каждой из четырёх точек подтверждения агент ждёт вашего «ок».

Для существующего кода без папки `.planning/` используется `gsd-onboard`: GSD
изучает проект и заводит для него дорожную карту. Новые функции в проекте на GSD
идут через `gsd-next` / `gsd-progress`, мелкие правки — через `gsd-quick --discuss`.
Частоту обновления, давность данных, поведение при сбоях и другие продуктовые
решения агент не придумывает: спрашивает.

## Что происходит автоматически

При установке стека глобально размещается [stack-start](../skills/stack-start/SKILL.md).
Его описание подходит обычным запросам на создание продукта; хуки SessionStart и
UserPromptSubmit напоминают агенту этот маршрут.

Агент определяет папку проекта и запускает поставляемый prepare_project.py: тот
ставит **локально и сразу** Impeccable (Codex — `.agents/skills/impeccable`,
Claude Code — `.claude/skills/impeccable`). Установка не требует заранее выбранного
интерфейса. Затем агент предлагает вести проект через GSD и после вашего согласия
запускает `gsd-new-project`.

Сам hook не скачивает пакеты в произвольную открытую папку. Он передаёт маршрут
агенту; агент выполняет подготовку в целевом проекте из вашего запроса. Для чтения
чужого репозитория и небольших правок набор автоматически не устанавливается.

## Что появляется в проекте

1. **Интервью и требования.** `gsd-new-project` задаёт вопросы о цели, пользователях,
   сценариях и границах, исследует область и записывает требования и дорожную карту
   в `.planning/`. Факты из кода и документов агент проверяет сам.
2. **Дизайн, если есть UI.** Если подключён Refero — сначала образцы реальных экранов
   и стилей, выбор направления вместе с вами. Затем Impeccable: `init` пишет
   PRODUCT.md, направление согласуется до реализации. Если milestone дорабатывает
   шаблон или дизайн-систему — сначала макеты всех блоков, потом код.
3. **Фазы.** План, выполнение с короткими проверками после каждой задачи и полной
   проверкой в конце плана, ревью (`gsd-code-review`), приёмка (`gsd-verify-work`)
   с проверкой страниц в браузере.
4. **Детали.** Emil уточняет взаимодействие, Agentation собирает замечания на странице.
   DESIGN.md описывает построенный визуальный мир по playbook Impeccable.

Для backend/CLI без интерфейса дизайн-процесс пропускается, skill остаётся локально.
Запись в Wiki требует отдельной просьбы.
