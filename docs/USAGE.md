# Коротко: как работать

Опишите результат обычным языком. Перечислять все skills в каждом запросе не нужно.

| Задача | Пример запроса |
|---|---|
| Начать большой проект | «Используй GSD: собери требования и разбей реализацию на проверяемые этапы» |
| Небольшой фикс | «Исправь этот баг, сохрани поведение и проверь затронутый сценарий» |
| API библиотеки | «Проверь через Context7 документацию для версии из package.json» |
| Дизайн страницы | «Используй Impeccable для этой страницы; сохрани контент и основной сценарий» |
| Компонент и motion | «С emil-design-eng проверь модальное окно: открытие, закрытие, клавиатура, reduced motion» |
| Code review | «Используй gstack review для текущего diff» |
| Проверка сайта | «Пройди основной сценарий через браузер и проверь мобильный размер» |
| Визуальные замечания | «Обработай мои аннотации Agentation для этой страницы» |
| Изучить связи | «Используй Graphify для этого модуля и покажи затрагиваемые вызовы» |
| Исследование | «Используй researcher, нужны первоисточники и дата проверки» |
| Проекты | «Найди проект в PROJECTS.md и проверь текущее состояние, только чтение» |
| Wiki | «Запиши это решение в space проекта через ObsidianDataWeave» |

Прямые вызовы: `$gsd-help`, `$impeccable`, `$emil-design-eng`, `$review`, `$qa`,
`$browse`, `$researcher`, `$graphify`, `$mtga status` — если соответствующий skill
установлен и обнаружен. У Context7 главным подтверждением служат MCP-инструменты,
а не наличие команды в списке skills.

Для нового UI: продуктовая задача → Impeccable → реализация с документацией
Context7 → нужные детали Emil → проверка браузером → замечания Agentation.
Это маршрут выбора, а не обязательный запуск всех инструментов при каждом изменении.

Если инструмент не появился, начните новую задачу, проверьте путь установки и
его ошибки. Не повторяйте установку вслепую. Проверки — в [VERIFY.md](VERIFY.md).
