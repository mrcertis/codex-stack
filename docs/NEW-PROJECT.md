# Начало нового проекта

Порядок: идея → grill-with-docs → требования → дизайн при наличии UI → документы
и код → проверка. Исправление небольшого бага не запускает этот процесс заново.

## Установка интервью

Источник: [mattpocock/skills](https://github.com/mattpocock/skills).

```bash
npx skills@latest add mattpocock/skills
```

Выберите Codex и три skills: **grill-with-docs**, **grilling**, **domain-modeling**.
Их можно установить глобально. Проверьте наличие всех трёх SKILL.md; для
domain-modeling нужны также поставляемые reference-файлы. Уже работающие
одноимённые skills не дублируйте, проверьте их происхождение и совместимость.

## Запрос для нового проекта

> $grill-with-docs Хочу создать [описание идеи]. Проведи интервью, изучи доступные файлы и источники, согласуй со мной понимание продукта. Зафиксируй требования и термины без дублирования документов. После этого, если нужен интерфейс, установи Impeccable локально в этот репозиторий и проведи выбор дизайн-направления. Затем подготовь нужные документы, реализуй и проверь результат. Уже известные ответы не спрашивай повторно.

Явный вызов важен: upstream grill-with-docs имеет `disable-model-invocation: true`.
Хук напоминает маршрут, но не снимает это ограничение и не начинает интервью
самостоятельно в фоне.

## Что появляется в проекте

1. **Интервью.** Grilling уточняет цель, пользователей, сценарии, границы и спорные
   решения. Агент самостоятельно проверяет факты, доступные в коде и документации.
   Реализация начинается после согласованного понимания.
2. **Требования.** `docs/brief.md` либо уже принятый документ требований: цель,
   пользователи, сценарии, ограничения, что не входит, критерии готовности.
   `CONTEXT.md` от domain-modeling — словарь предметной области, не замена brief.
   ADR создаются по необходимости для существенных решений.
3. **Дизайн, если есть UI.** [Установите локальный Impeccable](INSTALL.md#impeccable).
   Агент читает skill, запускает его context.mjs согласно текущей инструкции,
   переиспользует интервью в init и уточняет только пробелы. `init` пишет PRODUCT.md.
   Для нового визуального мира выбирается концепция и согласуется направление до
   реализации. `shape` сам по себе не означает готовую реализацию.
4. **Документы и код.** Технический план опирается на требования и выбранное
   направление. Большую работу можно вести через GSD, сохраняя результаты интервью.
   DESIGN.md и sidecar описывают построенный визуальный мир по завершающему
   playbook Impeccable; не создавайте фиктивный DESIGN.md после init.
5. **Проверка.** Критерии продукта, нужные тесты, реальные состояния интерфейса
   и размеры экрана. Emil уточняет взаимодействие, Agentation собирает замечания.

Для backend/CLI без интерфейса шаг Impeccable пропускается. Полная Wiki-компиляция
не является обязательной частью каждого старта; запись в Wiki требует запроса.
