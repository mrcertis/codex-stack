# Что делать после установки

После установки часть инструментов ещё требует входа, доверия к хукам или
подключения к конкретному проекту. Агент должен довести настройку до этих шагов
и показать, где требуется ваше действие. Повторно устанавливать весь стек не нужно.

Если установочная задача уже закончилась, напишите:

> Стек установлен. Помоги закончить настройку по https://github.com/mrcertis/codex-stack/blob/main/docs/AFTER-INSTALL.md и проверь, что всё работает.

## Один раз после установки

### 1. Откройте новую задачу Codex

Новая задача должна увидеть установленные skills, правила и MCP-подключения.
Если приложение не подхватило изменения, перезапустите его. Агент проверяет
доступность инструментов реальным вызовом, а не только наличием строки в конфиге.

### 2. Войдите в Context7

Если подключение уже отвечает на запросы, повторный вход не нужен. При настройке
через OAuth агент запускает вход для существующего MCP-сервера:

```bash
codex mcp login context7
```

Вы открываете выданную ссылку, входите в свой аккаунт и подтверждаете доступ.
Агент не должен просить пароль или код входа в чат. Если сервер ещё не добавлен,
агент сначала выполняет [настройку Context7](INSTALL.md#context7).

При подключении через API key OAuth не нужен: агент проверяет, что ваш ключ
доступен процессу Codex через настроенную переменную окружения. Сам ключ не
публикуется и не выводится в отчёт. Варианты подключения не дублируются.

**Проверка:** агент находит библиотеку и получает документацию через Context7
(resolve-library-id → query-docs). Например, проверяет работу очистки эффекта
в React. Успех — содержательный ответ из документации; запись «подключено»
без запроса недостаточна. [Источник и актуальная настройка](https://github.com/upstash/context7).

### 3. Подтвердите доверие к хукам

Откройте управление hooks в Codex: Settings → Hooks или `/hooks`, если этот
интерфейс поддерживается вашей версией. Просмотрите команды и подтвердите доверие
к установленным обработчикам стека и Z.A.E.B.A.L.

Агент проверяет их реальные события в новой задаче. Неподдерживаемый или
недоверенный hook остаётся незавершённым пунктом, а не отмечается рабочим.
Подробности: [хуки стека](HOOKS.md), [Z.A.E.B.A.L.](ZAEBAL.md).

### 4. Проверьте Agentation со стороны Codex

Agentation состоит из подключения к агенту и панели на странице. Глобальный MCP
настраивается один раз по [инструкции](INSTALL.md#agentation). Агент проверяет
запуск сервера и получает список сессий. Пустой список до открытия первой страницы
нормален; ошибка соединения — нет.

Для локального варианта отдельный вход в аккаунт Agentation не требуется.
Если порт 4747 уже занят, агент выясняет, какой сервер его использует, и согласует
подключение к нему или другой порт; не запускает бесконечно новые экземпляры.
Настройка панели описана ниже. [Как связаны панель и MCP](https://www.agentation.com/mcp).

### 5. Завершите настройку Wiki и дополнительных сервисов

Если вы хотите вести Wiki, укажите один общий каталог и разрешите создать или
использовать его. Агент проверяет пути и работу ObsidianDataWeave. Инициализация
и пробная запись выполняются по вашему запросу; пустой путь в шаблоне не означает
готовую базу знаний. Существующий vault и реестр проектов сохраняются.

Google Drive, NotebookLM и другие дополнительные подключения требуют собственного
входа только если вы решили ими пользоваться. Для внешнего аудитора Z.A.E.B.A.L.
агент отдельно проверяет авторизацию выбранного CLI; не просит логиниться во все
сервисы сразу. Браузерные инструменты могут потребовать загрузки браузера или
разрешений ОС — агент показывает конкретный оставшийся шаг.

## Для каждого проекта

### 1. Откройте нужный проект и опишите задачу

Например: «Давай сделаем сайт для [название проекта]». Агент подготавливает
локальный набор, включая Impeccable, проводит интервью и переходит к дизайну,
если нужен интерфейс. Подробности — [старт проекта](NEW-PROJECT.md).
После появления проектных hooks проверьте их доверие отдельно: глобальное
подключение не доказывает работу локальных обработчиков Impeccable.

### 2. Подключите замечания на странице

Когда у проекта появилась локальная страница, можно написать:

> Хочу оставлять замечания прямо на странице. Подключи это здесь.

Агент выбирает Agentation и выполняет проектную часть настройки:

1. Проверяет стек и уже существующую интеграцию. Для React 18+ добавляет пакет
   штатным менеджером проекта и монтирует панель один раз, только в development.
   Для другого стека подбирает совместимую dev-интеграцию и проверяет её отдельно.
2. Связывает панель с работающим локальным MCP-сервером. По умолчанию endpoint —
   `http://localhost:4747`; при смене порта обе стороны должны совпадать.
3. Запускает приложение и открывает его в настольном браузере. Панель не должна
   появляться в production; агент проверяет production build и его страницу.

Эту часть повторяют для каждого приложения, в котором нужны замечания.
Глобальная установка MCP не добавляет панель во все проекты автоматически.
Команды и пример компонента: [проектная установка](INSTALL.md#agentation),
[официальный репозиторий](https://github.com/benjitaylor/agentation).

### 3. Проверьте одно замечание от начала до конца

Нажмите на панель, выберите элемент страницы и оставьте тестовое замечание.
Напишите агенту: «Я оставил замечание, посмотри». Он должен получить его через
MCP и назвать тот же текст и элемент именно этого проекта.

После этого можно писать «Исправь мои замечания». Агент вносит изменения,
проверяет страницу и только затем закрывает выполненные замечания.
Постоянное наблюдение требует отдельной просьбы; установка сама его не запускает.

## Чем должна закончиться настройка

Агент показывает короткий отчёт: что проверено реальным действием, что требует
вашего входа или подтверждения и что пока не проверено. У каждого незавершённого
пункта есть следующий шаг. Полный список проверок — [VERIFY.md](VERIFY.md).

Дальше работайте обычными словами. Писать названия skills и помнить команды
не требуется — их выбор остаётся задачей агента.
