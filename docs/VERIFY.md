тестовый сигнал и ничего на похвалу, с временным состоянием и без внешнего аудитора.

trust нового пользователя.

Подготовка нового проекта дополнительно выполнена реальными upstream-установщиками

**Чистая установка полного стека на новом компьютере не выполнена в рамках
публикации репозитория.** Предыдущие проверки отдельных инструментов на машине
автора не доказывают совместимость любой будущей версии и ОС.

## Типичные проблемы

- MCP есть в конфиге, но нет tools: новый сеанс, `claude mcp list` или `/mcp`
  (в Codex — новая задача), проверка запуска сервера, авторизации, stderr и
  доступности исполняемого файла.
- Context7 возвращает 401: проверьте вход или наличие переменной в процессе агента,
  не печатая её значение. При 429 дождитесь снятия ограничения.
- CLI работает в терминале, но не в desktop: проверьте PATH; используйте абсолютный
  путь к установленному бинарю в локальном конфиге.
- Agentation doctor жалуется на другой клиент: проверяйте фактический MCP своего
  хоста, а не только диагностику другого клиента. Сетевой sandbox может мешать health-check.
- Порт 4747 занят: выясните, какой процесс слушает, прежде чем запускать второй.
  Не останавливайте неизвестный процесс. При смене порта синхронизируйте endpoint.
- Skill продублирован: сравните источники ~/.claude/skills, ~/.agents/skills и ~/.codex/skills;
  сохраните одну актуальную установку, удаление согласуйте.
- Hooks не выполняются: поддержка события, путь, разрешения и trust проверяются
  отдельно. Наличия записи в settings.json или hooks.json недостаточно.

## Проверка самого репозитория

```bash
python3 scripts/validate.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests
git diff --check
```

Перед push просмотрите staged diff и список файлов. Реальные config.toml,
settings.json, PROJECTS.md, backup и Wiki остаются локально.
