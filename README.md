# Codex Stack — mrcertis

Мой набор инструментов для работы с AI-агентами: от постановки задачи до кода, дизайна, проверки и проектной Wiki. Основной хост — **Codex**; **Claude Code** читает те же правила через одну строку в CLAUDE.md. Основа — [KISA Stack](https://github.com/howdeploy/kisa-stack), дополненная **GSD, Ponytail, Impeccable, Refero, Emil Design Engineering и Context7**.

Это открытая сборка инструкций и шаблонов. Она помогает воспроизвести подход, не копируя чужие ключи, личные проекты и настройки компьютера. Старый глобальный AGENTS.md сохраняется в приватной резервной копии и полностью заменяется шаблоном стека. Остальная конфигурация сохраняется.

**Что нового (14 октября 2026):** вся разработка идёт через GSD, gstack выведен из стека, Tools и Wiki вынесены из iCloud, добавлены четыре точки подтверждения и правила скорости, Ponytail 5.2.0 в Codex и Claude Code, MTGA включён по умолчанию, Refero рекомендуется для дизайна. [Подробно](CHANGELOG.md).

## Быстрый старт

1. Установите и авторизуйте Codex. Нужны Git, Node.js LTS; для полного набора также Python 3.11+, uv и Bun. Claude Code — по желанию.
2. Напишите агенту:

   > Установи и настрой мне этот стек: https://github.com/mrcertis/codex-stack. Следуй инструкции docs/AGENT-SETUP.md из репозитория и проверь результат.

   Агент сам получает репозиторий, читает инструкцию и выполняет настройку.
3. Пройдите [«Что делать после установки»](docs/AFTER-INSTALL.md): входы, доверие к хукам и проверка подключений.
4. Начинайте работу по [шпаргалке](docs/USAGE.md): новый проект — «Давай сделаем сайт для [название]», существующий код — `$gsd-onboard`, дальше всегда `$gsd-next`.

**Уже стоит старая версия (с gstack)?** Напишите агенту:

> Обнови мой стек по https://github.com/mrcertis/codex-stack/blob/main/docs/UPGRADE.md. Перед каждым удалением покажи список и спроси меня.

**Вручную:** [полная установка](docs/INSTALL.md). **Для агента:** [порядок настройки](docs/AGENT-SETUP.md). **На каждый день:** [как начинать задачу](docs/USAGE.md).

## Как это работает

Вы пишете идею обычными словами. Хук направляет агента к стартовому skill: тот ставит в проект Impeccable и передаёт работу в `gsd-new-project`. GSD задаёт вопросы, записывает требования и дорожную карту и ведёт проект по фазам: обсуждение → план → выполнение → проверка. [Как устроен старт](docs/NEW-PROJECT.md).

Агент останавливается в четырёх точках — после интервью, после плана, после выполнения и после приёмки — и пишет обычным языком: как понял, что сделает, чего не делает, как проверим. Дальше — только после вашего «ок». Проверки идут реже, но в нужных местах: тяжёлые — в конце плана, полная матрица экранов — в конце фазы. Вопросы о виде — с картинками.

Агент не придумывает интервалы обновления, сроки устаревания данных и поведение при сбоях; новые продуктовые вопросы согласуются до реализации зависимой части. [Глобальное правило](global-config/AGENTS.md#обязательное-уточнение-требований-перед-реализацией).

Wiki одна для общего знания, внутри отдельные spaces; она и каталог инструментов лежат вне iCloud (`~/Knowledge`, `~/tools`). Реестр проектов приватный. Просьба «проверь проект» разрешает чтение, но не изменения. Запись в Wiki — по явному запросу.

## Совместимость и ограничения

- Основной сценарий: локальный Codex на macOS/Linux; Claude Code — дополнительно, с теми же правилами. На Windows команды shell выполняются в WSL; нативные пути и менеджеры пакетов требуют адаптации.
- MCP, skill, CLI и плагин — разные сущности. Наличие skill не означает, что MCP подключён.
- Refero для живого поиска требует платного тарифа; без него весь дизайн ведёт Impeccable.
- Это не обещание установки всего стека за пять минут. Авторизация, браузеры, hooks trust и проектные интеграции проверяются отдельно.
- Инструкции сверены 14 октября 2026. Upstream меняется; после обновления повторяйте проверки. См. [статус проверки](docs/VERIFY.md).
